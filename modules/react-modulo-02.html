2. Componentes, JSX e Interatividade

1. Criando Componentes (Aula 24)

No React moderno, toda a interface de usuário é construída a partir de blocos independentes, isolados e reutilizáveis chamados Componentes. Sob a ótica técnica da linguagem, um componente React é fundamentalmente uma função JavaScript que retorna uma interface visual (JSX).

A Regra Arquitetural de Ouro: Padrão PascalCase

A regra mais importante na criação de qualquer componente no React é que o seu nome deve obrigatoriamente começar com letra maiúscula, seguindo a convenção PascalCase (onde a primeira letra de cada palavra concatenada é maiúscula, como CabecalhoPrincipal, BotaoConfirmar ou CardProduto):

  • Tags com letra minúscula (ex: <div>, <h1>, <header>): O compilador do React interpreta como elementos HTML nativos da especificação W3C e envia uma string literal (como "div") diretamente para o DOM do navegador.
  • Tags com letra maiúscula (ex: <CabecalhoPrincipal />, <Botao />): O React reconhece que se trata de um componente customizado criado por você, procurando a função JavaScript correspondente no escopo do arquivo para executá-la e renderizar o seu retorno.

⚠️ Armadilha Clássica de Iniciantes: Se você declarar uma função com letra minúscula como function meuBotao() e tentar usá-la no JSX como <meuBotao />, o React não executará a sua função! Ele tentará criar uma tag HTML inexistente chamada <meubotao> no navegador e exibirá um aviso no console. Sempre utilize PascalCase para componentes!

As Duas Formas de Declarar Componentes Funcionais

Desde a introdução dos Hooks (React 16.8+), componentes baseados em classes (Class Components) tornaram-se legados. Hoje, 100% dos novos projetos utilizam Function Components (Componentes Funcionais), que podem ser declarados de duas maneiras equivalentes em JavaScript:

// 1. Function Declaration (Sintaxe clássica e tradicional do JavaScript)
function MeuComponente() {
  return <h2>Olá, eu sou um componente declarado com function!</h2>;
}

// 2. Arrow Function (Sintaxe ES6+ amplamente adotada no mercado)
const MeuComponenteArrow = () => {
  return <h2>Olá, eu sou um componente em Arrow Function!</h2>;
};

// 2.1 Arrow Function com Retorno Implícito (quando o componente apenas retorna JSX direto)
const BadgeStatus = () => <span className="badge">Ativo</span>;

Tabela Comparativa: Function Declaration vs. Arrow Function

Característica Function Declaration (function Nome() {}) Arrow Function (const Nome = () => {})
Comportamento no React Idêntico: recebe props, gerencia estado (Hooks) e retorna JSX Idêntico: não há diferença de performance ou ciclo de vida no React
Hoisting (Içamento JS) Sofre hoisting: pode ser chamada antes da linha em que foi declarada no arquivo Não sofre hoisting: deve ser declarada antes de ser utilizada no código
Retorno Implícito Não possui: exige sempre a palavra-chave return e chaves { } Suporta retorno direto sem a palavra return para expressões puras
Exportação Direta na Linha Suporta tanto export default function Nome() quanto export function Nome() Suporta export const Nome = ... (para default, exporta-se no fim do arquivo)

💡 Boas Práticas de Arquitetura: Independentemente de escolher function tradicional ou Arrow Function, mantenha a consistência no projeto. Além disso, nunca declare um componente dentro do corpo de outro componente: isso faria o componente filho ser recriado do zero na memória a cada renderização, destruindo seu estado e prejudicando a performance.

2. Importação e Exportação de Componentes (Aula 25)

Em uma aplicação profissional, colocar dezenas de componentes dentro de um único arquivo App.jsx tornaria a manutenção caótica e inviável. Para manter o código limpo, organizado e escalável (Seguindo o princípio de responsabilidade única), o React utiliza nativamente o sistema de Módulos do ECMAScript 6 (ES6 Modules / ESM).

A convenção de mercado consiste em criar uma pasta src/components/, separar cada componente em seu próprio arquivo .jsx (ex: src/components/Botao.jsx), exportá-lo na origem e importá-lo onde for necessário.

Fluxo de modularização ES6 no React: componentes isolados em src/components/ são exportados via Default ou Named Export e compostos na árvore principal dentro do App.jsx

As Duas Modalidades de Exportação no ES6

  1. Exportação Padrão (export default):
    • Permite exportar apenas um único componente principal por arquivo.
    • Na hora de importar em outro arquivo, não se utilizam chaves (import Botao from './components/Botao').
    • Tecnicamente, o JavaScript permite que você dê qualquer nome na importação default, mas a convenção profissional estrita é manter exatamente o mesmo nome PascalCase do componente e do arquivo.
  2. Exportação Nomeada (export / Named Export):
    • Permite exportar múltiplos componentes, variáveis ou funções auxiliares a partir de um mesmo arquivo (ex: um arquivo Icones.jsx ou Botoes.jsx que agrupa variações).
    • Na hora de importar, é obrigatório o uso de chaves { } com o nome exato que foi exportado (ex: import { BotaoPrimario, BotaoSecundario } from './components/Botoes').
    • Caso haja conflito de nomes no arquivo de destino, você pode criar um apelido (alias) usando a palavra-chave as: import { BotaoPrimario as BotaoPrincipal } from './components/Botoes'.

Exemplo Prático Completo: Exportando e Importando Componentes

// ==========================================================
// 1. Arquivo: src/components/Botao.jsx (Exportação Default)
// ==========================================================
function Botao() {
  return <button className="btn-padrao">Clique Aqui</button>;
}

export default Botao; // Exportação Padrão (1 por arquivo)


// ==========================================================
// 2. Arquivo: src/components/Alertas.jsx (Exportação Nomeada)
// ==========================================================
export function AlertaSucesso() {
  return <div className="alerta-verde">Operação realizada com sucesso!</div>;
}

export const AlertaErro = () => {
  return <div className="alerta-vermelho">Falha ao processar requisição.</div>;
};


// ==========================================================
// 3. Arquivo: src/App.jsx (Consumindo os Módulos)
// ==========================================================
import Botao from './components/Botao'; // Import Default (Sem chaves)
import { AlertaSucesso, AlertaErro } from './components/Alertas'; // Import Nomeado (Com chaves)

function App() {
  return (
    <div>
      <h1>Minha Aplicação Modular</h1>
      <AlertaSucesso />
      <Botao /> {/* Instanciando o componente como uma tag */}
      <AlertaErro />
    </div>
  );
}

export default App;

Critério Exportação Padrão (export default) Exportação Nomeada (export { ... })

3. Conhecendo o JSX (Aula 26)

O JSX (JavaScript XML) é uma extensão de sintaxe para o JavaScript criada pela equipe do React. Embora visualmente pareça código HTML colado dentro de uma função JavaScript, o navegador não compreende JSX nativamente.

O que acontece nos bastidores? Quando você salva o seu arquivo .jsx, o transpilador embutido no Vite (esbuild / Babel) intercepta cada tag JSX e a converte em chamadas de função JavaScript puras (React.createElement ou a função moderna _jsx do runtime automático), que retornam objetos JavaScript representando a árvore do Virtual DOM.

Pipeline de compilação do JSX: o código declarativo escrito pelo desenvolvedor passa pela validação sintática do transpilador no Vite e é convertido em chamadas React.createElement() no navegador

As 5 Regras Estritas do JSX

Por ser traduzido diretamente em expressões e objetos JavaScript, o JSX impõe cinco regras sintáticas obrigatórias que o diferenciam do HTML comum:

  1. Regra 1 — Um Único Elemento Pai (Root Element) e Fragmentos (<> ... </>):
    • Em JavaScript, uma função só pode retornar um único valor/objeto no seu return. Portanto, um componente não pode devolver dois elementos irmãos soltos lado a lado (ex: um <h1> seguido de um <p> sem um container pai).
    • Você pode envolvê-los em uma <div> ou <section>. Porém, adicionar <div> desnecessárias polui o HTML final e pode quebrar regras de CSS (como layouts Flexbox ou CSS Grid).
    • A Solução Elegante — React Fragment (<> ... </>): O Fragmento é uma tag vazia especial do React que cumpre a regra do elemento pai único no JSX, mas é totalmente invisível no navegador (não gera nenhum nó extra no DOM real!).
  2. Regra 2 — Palavras Reservadas do JavaScript (className e htmlFor):
    • Como o JSX vive dentro de um arquivo JavaScript, não podemos usar atributos HTML cujos nomes colidem com palavras-chave reservadas da gramática do JavaScript.
    • class vira className: Em JS, class é a palavra reservada para criar classes de Orientação a Objetos. Por isso, para estilizar com CSS no JSX, usamos className="meu-estilo" (que se baseia na propriedade nativa element.className da API do DOM).
    • for vira htmlFor: Em JS, for declara um laço de repetição. Portanto, para associar uma tag <label> ao id de um <input>, utiliza-se <label htmlFor="campo-email">.
  3. Regra 3 — Padrão camelCase para Atributos Compostos e Eventos:
    • Todos os atributos HTML formados por duas palavras e todos os manipuladores de eventos são escritos em camelCase (primeira palavra minúscula, segunda com inicial maiúscula).
    • Exemplos: onclick vira onClick; onchange vira onChange; tabindex vira tabIndex; maxlength vira maxLength; readonly vira readOnly; stroke-width (em SVGs) vira strokeWidth.
  4. Regra 4 — Fechamento Obrigatório de Todas as Tags (Self-Closing Tags):
    • O HTML5 é permissivo e aceita tags vazias abertas como <input type="text">, <img src="...">, <br> e <hr>.
    • O JSX segue a rigidez do XML: absolutamente toda tag precisa ser fechada. Tags que não possuem conteúdo filho devem terminar obrigatoriamente com barra antes do sinal de maior: <input type="text" />, <img src="..." />, <br /> e <hr />.
  5. Regra 5 — Interpolação de Expressões JavaScript com Chaves { }:
    • Para exibir o valor de variáveis, executar cálculos matemáticos, formatar textos ou renderizar listas dinamicamente dentro do JSX, basta abrir e fechar chaves { }. Tudo o que estiver dentro de { } é avaliado como uma expressão JavaScript em tempo real.
// Exemplo reunindo todas as regras do JSX na prática:
function FormularioCadastro() {
  const textoBotao = "Enviar Cadastro";

  // CORRETO: Envolvido por um Fragmento React <> </> (não gera div inútil no DOM)
  return (
    <>
      <label htmlFor="nome">Nome Completo:</label>
      <input
        type="text"
        id="nome"
        className="input-estilizado"
        maxLength={60}
        placeholder="Digite seu nome..."
      />
      <button type="button" onClick={() => alert("Enviado!")}>
        {textoBotao.toUpperCase()}
      </button>
    </>
  );
}

export default FormularioCadastro;

4. Comentários nos Componentes (Aula 27)

Documentar trechos importantes ou desativar temporariamente elementos durante um debug faz parte da rotina de qualquer desenvolvedor. No React, como um arquivo .jsx mistura lógica imperativa JavaScript com marcação declarativa JSX, a sintaxe para escrever comentários muda de acordo com a região do arquivo em que o seu cursor está posicionado.

As Duas Zonas de Comentário em um Arquivo .jsx

  1. Zona 1 — Fora do retorno JSX (Na Área Lógica do JavaScript):
    • Antes da instrução return ( (onde você declara variáveis, funções auxiliares, chamadas de API e Hooks) ou fora da função do componente, você está em um ambiente 100% JavaScript padrão.
    • Utilize normalmente:
      • // Comentário de linha única
      • /* Comentário de bloco para múltiplas linhas */
  2. Zona 2 — Dentro do retorno JSX (No Meio das Tags da Interface):
    • Assim que você entra dentro da árvore de tags do return ( ... ), as regras mudam completamente:
      • Se você tentar usar o comentário do HTML (<!-- erro -->), o compilador do React apontará erro imediato de sintaxe.
      • Se você digitar // comentário solto entre duas tags, o React achará que aquilo é um texto comum e imprimirá as barras literalmente na tela do usuário!
    • A Sintaxe Correta no JSX ({/* ... */}): Você deve primeiro abrir chaves { } (para avisar ao React que está abrindo uma janela de código JavaScript) e, dentro das chaves, usar o comentário de bloco: {/* Seu comentário JSX aqui */}.

Exemplo Prático: Comentários na Área Lógica vs. Área JSX

// Comentário de topo de arquivo: Componente de exibição de perfil do usuário
function Perfil() {
  // 1. FORA DO RETURN (JavaScript normal):
  // Aqui definimos as variáveis e regras de negócio do componente
  const usuario = "Eduardo";
  const cargo = "Cloud & Frontend Developer";

  /*
    Também podemos usar comentários de múltiplas linhas padrão do JS
    antes de chegar na cláusula return.
  */

  return (
    <div className="card">
      {/* 2. DENTRO DO RETURN (Sintaxe híbrida JSX): */}
      {/* Obrigatório envolver o comentário de bloco com chaves { } */}
      <h2>{usuario}</h2>
      <p>{cargo}</p>

      {/* 
        Dica de Debug: Você também pode comentar tags inteiras no JSX
        para ocultá-las temporariamente sem apagar o código:
        <button>Editar Perfil</button>
      */}
    </div>
  );
}

export default Perfil;

⌨️ Dica de Produtividade no VS Code (Linux/Ubuntu): Você não precisa digitar {/* */} manualmente! Basta posicionar o cursor na linha desejada (ou selecionar o bloco de tags) e pressionar o atalho de comentário do VS Code (Ctrl + ; em teclados ABNT2 ou Ctrl + / em teclados US). O VS Code reconhece automaticamente se o cursor está antes do return (inserindo //) ou dentro do bloco JSX (inserindo {/* ... */} automaticamente).

5. Template Expressions (Aula 28)

No React, o JSX permite que você misture marcação estrutural (HTML) com a lógica da programação (JavaScript) de maneira fluida e declarativa. Uma Template Expression é a injeção de código JavaScript diretamente dentro do JSX através do uso de chaves { }.

Sempre que o React encontra um par de chaves { } no meio do JSX, ele abre uma "janela de execução JavaScript": tudo o que estiver lá dentro é avaliado (calculado) em tempo real e o resultado final é renderizado na tela.

A Regra Fundamental: Expressões (Permitido) vs. Declarações de Bloco (Proibido)

Por baixo dos panos, o valor colocado dentro de { } é passado como argumento para a função React.createElement(...). Por esse motivo técnico, apenas Expressões JavaScript (código que resolve e retorna um valor) são permitidas dentro das chaves:

  • ✅ O que é PERMITIDO dentro de { } (Expressões que retornam valor):
    • Leitura de variáveis e constantes ({nome}) ou propriedades de objetos ({usuario.cargo}).
    • Operações matemáticas e aritméticas ({2 + 2}, {2026 - idade}, {preco * 1.15}).
    • Concatenação de strings e métodos nativos ({nome.toUpperCase()}).
    • Chamadas de funções que retornam valores ou outros blocos de JSX ({formatarNome(nome)}).
    • Operadores ternários ({condicao ? 'Sim' : 'Não'}) e operadores lógicos de curto-circuito ({logado && <Painel />}).
  • ❌ O que NÃO é permitido dentro de { } (Declarações de Controle de Bloco):
    • Estruturas de controle imperativas como if / else, switch / case, for ou while não podem ser escritas diretamente dentro das chaves no meio do JSX, pois em JavaScript blocos de controle não retornam um valor como expressão e causam erro imediato de compilação (SyntaxError: Unexpected token).

Exemplo em Código: Template Expressions na Prática

function PerfilUsuario() {
  const nome = "Eduardo";
  const idade = 30;
  const dadosExtras = { profissao: "Arquiteto Cloud & React", cidade: "São Paulo" };

  // Função auxiliar que processa o texto e retorna uma string formatada
  const formatarNome = (texto) => texto.toUpperCase();

  return (
    <div className="perfil-card">
      {/* Injetando variáveis, propriedades de objeto e executando funções */}
      <h2>Bem-vindo, {formatarNome(nome)}!</h2>
      <p>Atuação: {dadosExtras.profissao} ({dadosExtras.cidade})</p>
      <p>Você nasceu no ano de {2026 - idade}.</p>
      <p>Status da Conta: {idade >= 18 ? "Maior de Idade (Ativo)" : "Menor de Idade"}</p>
    </div>
  );
}

export default PerfilUsuario;

Tabela de Referência: O que colocar dentro das Chaves { }

Tipo de Código Sintaxe no JSX Status Explicação Técnica
Variáveis e Objetos <p>{nome} - {user.email}</p> ✅ Válido Resolve diretamente para o valor primitivo (string/number)
Expressão Matemática <span>{2026 - idade}</span> ✅ Válido A expressão aritmética é calculada e retorna o número final
Chamada de Função <h2>{formatarNome(nome)}</h2> ✅ Válido A função é executada e seu return é injetado no JSX
Operador Ternário {ativo ? <Sim /> : <Nao />} ✅ Válido Ternário é uma expressão em JS que devolve um dos dois lados
Bloco if / else ou for {if (ativo) { return ... }} ❌ Erro Statements de bloco não são expressões; use ternário ou função de renderização

⚠️ Atenção com Valores Booleanos, Null e Undefined: Em Template Expressions, valores como {true}, {false}, {null} e {undefined} são ignorados visualmente pelo React e não imprimem nada na tela (isso é proposital para permitir renderização condicional). Caso queira exibir literalmente a palavra "true" ou "false" na tela, converta para string com {String(valorBooleano)}. Da mesma forma, você não pode passar um objeto inteiro direto no JSX ({dadosExtras} dá erro); acesse suas propriedades individuais ({dadosExtras.profissao}).

6. Hierarquia de Componentes: Relação Pai e Filho (Aula 29)

A arquitetura de qualquer aplicação React real é estruturada como uma Árvore Genealógica de Componentes (Component Tree), na qual componentes maiores e mais abrangentes encapsulam componentes menores e especializados. Essa estrutura estabelece a relação fundamental de Componente Pai (Parent) e Componente Filho (Child).

Como funciona a Relação Pai e Filho?

  • Componente Pai (Parent Component): É o componente que importa e instancia outro componente dentro do seu próprio bloco return. Ele atua como um agrupador estrutural ou orquestrador (ex: App, PainelControle, BarraNavegacao).
  • Componente Filho (Child Component): É o componente menor que é renderizado dentro do Pai (ex: BotaoAcao, AvatarUsuario, ItemMenu).
  • Reaproveitamento em Cascata: Um componente Filho pode ser reutilizado dezenas de vezes dentro do mesmo Pai ou em múltiplos Pais diferentes ao redor do sistema. Além disso, um Filho também pode ser Pai de outros componentes ainda menores (Netos), formando uma hierarquia limpa e modular.

Exemplo em Código: Composição entre Pai e Filho

// 1. Componente Filho (Bloco atômico e reutilizável)
function BotaoAcao() {
  return <button className="btn-salvar">Salvar Alterações</button>;
}

// 2. Componente Pai (Encapsula e organiza componentes menores)
function PainelControle() {
  return (
    <div className="painel">
      <h3>Configurações da Conta</h3>
      <p>Gerencie suas preferências de segurança e notificações.</p>
      
      {/* O Pai "PainelControle" está renderizando o Filho "BotaoAcao" */}
      <BotaoAcao />
    </div>
  );
}

export default PainelControle;

7. Eventos nos Componentes (Aula 30)

Em uma aplicação web moderna, a interface precisa reagir instantaneamente às ações do usuário: cliques em botões, digitação em campos de busca, envio de formulários e movimentos do mouse. No React, toda essa interatividade é controlada por um sistema próprio de eventos de alta performance chamado Synthetic Events (Eventos Sintéticos).

O que são Synthetic Events (Eventos Sintéticos)?

  • Camada de Padronização Cross-Browser: Historicamente, navegadores diferentes (Chrome, Firefox, Safari, Edge) implementavam pequenos detalhes de eventos nativos do DOM de maneiras distintas. O React resolve isso criando uma camada de abstração (um wrapper chamado SyntheticBaseEvent) por cima do evento nativo do navegador.
  • Comportamento 100% Idêntico: Independentemente de o seu usuário estar acessando pelo Safari no iOS, Firefox no Linux Ubuntu ou Chrome no Windows, o evento sintético do React terá exatamente as mesmas propriedades e métodos (como e.target.value, e.preventDefault() e e.stopPropagation()).
  • Delegação Inteligente na Raiz (Event Delegation): Em vez de pendurar milhares de event listeners pesados diretamente em cada botão ou input do DOM real, o React anexa um único ouvinte centralizado no container raiz (#root) e gerencia o roteamento dos eventos na memória com altíssima eficiência.

As Regras de Sintaxe para Eventos no JSX

Ao migrar do HTML tradicional para o JSX do React, existem duas regras sintáticas fundamentais para declarar eventos:

  1. Nomenclatura em camelCase:
    • No HTML clássico, os atributos de evento são escritos inteiramente em letras minúsculas (onclick, onchange, onsubmit).
    • No React, você sempre utilizará o padrão camelCase: onClick, onChange, onSubmit, onMouseEnter, onKeyDown.
  2. Passagem de Função via Chaves { } (e não String):
    • No HTML tradicional, você passava uma string contendo o código a ser executado: onclick="alert('Olá')".
    • No React, você passa a referência da função JavaScript diretamente dentro de uma Template Expression { }: onClick={lidarComClique}.

Evento no HTML Evento no React (JSX) Quando é Disparado Elementos Mais Comuns
onclick onClick Quando o usuário clica sobre o elemento <button>, <a>, <div>
onchange / oninput onChange A cada tecla digitada ou alteração de valor do campo <input>, <select>, <textarea>
onsubmit onSubmit Quando o formulário é submetido (clique no submit ou tecla Enter) <form>
onkeydown onKeyDown Quando o usuário pressiona uma tecla física do teclado <input>, atalhos globais
onmouseenter onMouseEnter Quando o cursor do mouse entra na área do elemento (hover) Cards, menus dropdown, tooltips

8. Funções nos Eventos (Aula 31)

A maneira como você conecta uma função JavaScript a um evento no JSX determina quando e como essa lógica será disparada. Existe uma armadilha clássica com o uso de parênteses () que todo desenvolvedor React precisa dominar desde o início.

Fluxo dos Eventos Sintéticos do React e comparação visual entre passagem por referência (sem argumentos), Arrow Function anônima (com argumentos) e captura do Objeto de Evento (e)

Os 3 Cenários de Atrelamento de Funções aos Eventos

  1. Cenário 1 — Passando por Referência (Função sem argumentos):
    • Quando a sua função não precisa receber parâmetros customizados, você deve passar apenas o nome da função (sua referência na memória): onClick={lidarComClique}.
    • Por que NUNCA colocar parênteses (onClick={lidarComClique()})? Em JavaScript, colocar () ao lado do nome de uma função ordena sua execução imediata. Se você escrever onClick={lidarComClique()}, a função será disparada sozinha no instante em que o React estiver desenhando a tela (antes mesmo de o usuário tocar no mouse!).
  2. Cenário 2 — Arrow Function Inline (Função que exige argumentos):
    • E quando você precisa passar um parâmetro para a função, como o nome de um usuário ou o ID de um item para deletar (saudarUsuario("Eduardo"))?
    • Como não podemos escrever onClick={saudarUsuario("Eduardo")} diretamente (pois os parênteses executariam a função na hora da renderização), a solução arquitetural é embrulhar a chamada dentro de uma Arrow Function anônima: onClick={() => saudarUsuario("Eduardo")}.
    • Dessa forma, o que você está entregando para o onClick é a declaração da arrow function anônima (() => ...), que ficará aguardando quieta na memória e só executará saudarUsuario("Eduardo") quando o clique realmente acontecer!
  3. Cenário 3 — O Objeto de Evento Sintético (e):
    • Em todos os eventos (especialmente em onChange de inputs e onSubmit de formulários), o React injeta automaticamente como primeiro argumento da sua função o Objeto de Evento Sintético, tradicionalmente chamado de e ou event.
    • Através dele, você acessa propriedades vitais:
      • e.target.value: Retorna o texto exato que o usuário acabou de digitar dentro de um <input> ou a opção escolhida em um <select>.
      • e.preventDefault(): Cancela o comportamento padrão do navegador (como impedir que um <form onSubmit={...}> recarregue a página inteira).

Documentação em Código: Os 3 Cenários na Prática

function FormularioInterativo() {

  // 1. Função simples sem argumentos
  const lidarComClique = () => {
    console.log("O botão foi clicado!");
  };

  // 2. Função que exige um argumento customizado
  const saudarUsuario = (nome) => {
    console.log(`Olá, ${nome}!`);
  };

  // 3. Função que captura o objeto do evento sintético (e)
  const capturarDigitacao = (e) => {
    console.log("O usuário digitou:", e.target.value);
  };

  // 4. Bônus: Função de envio de formulário usando e.preventDefault()
  const enviarFormulario = (e) => {
    e.preventDefault(); // Evita o reload padrão da página no navegador!
    console.log("Formulário enviado via SPA sem recarregar a tela!");
  };

  return (
    <div className="painel-interativo">

      {/* CENÁRIO 1: Passando apenas a referência (SEM parênteses) */}
      <button onClick={lidarComClique}>Clique Simples</button>

      {/* CENÁRIO 2: ERRADO seria onClick={saudarUsuario("Eduardo")} -> Executaria sozinho ao carregar a tela! */}
      {/* CORRETO: Usando uma arrow function anônima para atrasar a execução até o clique */}
      <button onClick={() => saudarUsuario("Eduardo")}>Dizer Olá</button>

      {/* CENÁRIO 3: Capturando o evento de digitação em tempo real via (e.target.value) */}
      <form onSubmit={enviarFormulario}>
        <label htmlFor="pesquisa">Pesquisar:</label>
        <input
          type="text"
          id="pesquisa"
          onChange={capturarDigitacao}
          placeholder="Digite algo..."
        />
        <button type="submit">Buscar</button>
      </form>

    </div>
  );
}

export default FormularioInterativo;

💡 E se eu precisar passar um argumento customizado E TAMBÉM o objeto de evento (e)? Muito simples! Na Arrow Function anônima, basta receber o (e) no primeiro parêntese e repassá-lo para a sua função junto com o seu argumento: onClick={(e) => deletarProduto(produto.id, e)}.

9. Função de Renderização (Aula 32)

Como vimos nas Template Expressions, não podemos jogar um bloco if / else if / else diretamente dentro das chaves { } no meio do JSX. Quando temos apenas 2 caminhos, o operador ternário (condicao ? A : B) resolve perfeitamente. Mas e quando a regra de negócio exige 3, 4 ou mais variações de interface dependendo do perfil do usuário ou do status de um pedido?

Aninhar múltiplos ternários um dentro do outro torna o return principal confuso e difícil de dar manutenção. A solução arquitetural elegante para esse cenário é criar uma Função de Renderização Secundária.

Como estruturar uma Função de Renderização

  1. Antes do return principal (dentro do escopo JavaScript do componente), você declara uma função auxiliar (normalmente prefixada com o verbo renderizar... ou render...).
  2. Dentro dessa função auxiliar, você tem total liberdade para usar estruturas imperativas do JavaScript como if / else if / else ou switch / case, fazendo cada ramificação retornar o seu respectivo bloco de JSX.
  3. No return principal do componente, você simplesmente invoca a função dentro de uma Template Expression: {renderizarPainel(nivelAcesso)}.

Exemplo em Código: Isolando Lógica Condicional Complexa

function Dashboard() {
  const usuarioLogado = true;
  const nivelAcesso = "admin"; // Experimente mudar para "funcionario" ou "visitante"

  // Função de renderização secundária: isola toda a complexidade de if/else fora do JSX principal
  const renderizarPainel = (nivel) => {
    if (nivel === "admin") {
      return (
        <div className="painel-admin">
          <h2>Acesso Total (Administrador)</h2>
          <p>Gerenciamento de Usuários, Auditoria Financeira e Vendas.</p>
        </div>
      );
    } else if (nivel === "funcionario") {
      return (
        <div className="painel-operacional">
          <h2>Acesso Parcial (Operacional)</h2>
          <p>Módulo exclusivo para registro de Vendas e Atendimento.</p>
        </div>
      );
    } else {
      return <div className="painel-bloqueado">Acesso Negado: Permissão insuficiente.</div>;
    }
  };

  // O return principal permanece extremamente limpo, semântico e fácil de ler!
  return (
    <div className="dashboard-container">
      <h1>Sistema Interno Corporativo</h1>
      {/* Chamando a função de renderização para injetar o JSX dinamicamente */}
      {usuarioLogado ? renderizarPainel(nivelAcesso) : <p>Faça login para continuar.</p>}
    </div>
  );
}

export default Dashboard;
