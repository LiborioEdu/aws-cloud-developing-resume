3. Developing Storage Solutions

1. Introduction

O foco absoluto deste módulo é dominar o Amazon S3 (Simple Storage Service), um dos serviços mais essenciais e cobrados da AWS.

  • Objetivos de Aprendizado: O módulo vai te ensinar a criar buckets (contêineres de armazenamento), gerenciar objetos (arquivos), proteger seus dados, controlar quem tem acesso a eles e, principalmente, como executar todas essas operações via código utilizando os AWS SDKs.
  • O Caso da Cafeteria (Cenário Prático): A desenvolvedora (Sofía) já configurou o ambiente de desenvolvimento e precisa criar um site de "prova de conceito" (proof-of-concept) para mostrar aos donos da cafeteria. O grande requisito de negócio aqui é a privacidade: o site deve ser criado, mas não pode ser exposto ao mundo externo ainda.
  • O Papel do S3 na Aplicação: Para atender a esse cenário, você aprenderá a usar o S3 para hospedagem de site estático (static website hosting). Para garantir a segurança e impedir que o público veja o site antes da hora, você aplicará uma Política de Bucket (bucket policy), que é uma regra de segurança configurada no S3 para limitar de onde os acessos podem vir.

2. Introducing Amazon S3

O Amazon S3 é o núcleo de armazenamento da AWS e um dos serviços mais cobrados em exames. Ele não opera como um disco rígido tradicional, mas sim como um serviço de armazenamento de objetos.

Principais Características do S3

  • Durabilidade extrema (11 noves): Projetado para 99,999999999% de durabilidade. Estatisticamente, se você armazenar 10 milhões de objetos, perderia apenas um a cada 10.000 anos.
  • Orientado a eventos: O S3 pode disparar ações automaticamente (notificando serviços como AWS Lambda, SNS ou SQS) sempre que um arquivo for criado, deletado ou restaurado.

Principais Casos de Uso

  • Hospedagem de site estático: Excelente para arquivos HTML, CSS e JavaScript (rodados no cliente). Atenção: O S3 não suporta processamento no lado do servidor (como PHP, Java ou ASP.NET).
  • Armazenamento e Distribuição: Guardar mídias e distribuí-las diretamente ou acelerar a entrega usando o Amazon CloudFront.
  • Backup e Arquivamento: Integração de ciclo de vida com o Amazon S3 Glacier para arquivar dados acessados raramente.
  • Data Lakes e Big Data: Repositório central para analisar volumes massivos de dados estruturados e não estruturados.
  • Recuperação de Desastres (DR): Uso da Replicação entre Regiões (CRR) para copiar dados automaticamente para outras áreas geográficas como medida de segurança.

Os Três Componentes Essenciais

  • Bucket: É o contêiner principal. Eles são Regionais (os dados nunca saem da região onde o bucket foi criado, a não ser que você configure uma transferência explícita). O bucket organiza os arquivos e centraliza o controle de acesso e os custos.
  • Object (Objeto): É o dado fundamental armazenado. Consiste no arquivo em si (foto, vídeo, documento) somado aos seus metadados (informações que descrevem o arquivo).
  • Key (Chave): É o identificador único do objeto dentro do bucket. Você pode pensar nela como o nome e o caminho do arquivo (ex: documentos/preview.mp4).

Ao juntar tudo isso, cada objeto ganha um endereço de URL único e estruturado:

https://s3-<aws-region>.amazonaws.com/<bucket-name>/<object-key>

3. Creating S3 Bucket

Nomenclatura de Buckets

O nome do seu bucket deve ser globalmente único em toda a AWS, independentemente de quem o criou. Se alguém no Japão usar um nome, você não poderá usá-lo no Brasil. Além disso, as regras são estritas:

  • Deve ter entre 3 e 63 caracteres.
  • Apenas letras minúsculas, números e hifens (-).
  • Proibido: Letras maiúsculas e underlines (_).
  • Atenção: O nome não pode ser alterado após a criação.

Escolha da Região

Ao criar o bucket, você define em qual região física ele existirá. Essa decisão é baseada em três fatores: Latência (proximidade com o usuário final), Custo e Requisitos Regulatórios (leis de onde os dados podem ser armazenados). A região também não pode ser alterada depois.

Acessando Buckets (URLs)

O S3 utiliza URLs no estilo Virtual-host, onde o nome do bucket faz parte do domínio principal.

  • Padrão: 
    http://<nome-do-bucket>.s3-<região>.amazonaws.com/<chave-do-objeto>
  • Site Estático: Quando o bucket é configurado para hospedar um site, a URL muda ligeiramente para incluir a palavra website (ex: ...s3-website-us-east-1...).

Estrutura de Pastas (Prefixos)

O S3 é um armazenamento plano, ou seja, não existem pastas reais. Para simular uma estrutura de diretórios, o S3 usa Prefixos (Prefixes). Quando você vê um arquivo em 2021/matematica/notas.txt, o S3 entende que o nome completo (a chave) do arquivo é todo esse caminho. O uso da barra (/) apenas cria a ilusão de pastas para organizar e facilitar a filtragem dos arquivos via código.

4. Working with S3 objects

Todo objeto no S3 é formado pelos dados (o arquivo em si) e pelos metadados (informações sobre o arquivo). Os metadados se dividem em dois tipos:

  • Definidos pelo Sistema: O próprio S3 gerencia. Alguns você não pode mudar (como data de criação e tamanho), outros você pode (como classe de armazenamento e criptografia).
  • Definidos pelo Usuário: Informações personalizadas que você mesmo atrela ao arquivo. Elas obrigatoriamente precisam começar com o prefixo x-amz-meta- (ex: x-amz-meta-nome-alternativo).

Operações Básicas: PUT, GET e DELETE

Para interagir com os objetos via API/Código, utilizamos três operações principais:

  • 1. PUT (Enviar/Fazer Upload): Faz o upload do objeto inteiro para o bucket.
    • Limites: O tamanho máximo de um objeto no S3 é de 5 TB.
    • Upload Simples: Usado para arquivos de até 5 GB.
    • Multipart Upload (Upload em Partes): O arquivo é quebrado em pedaços enviados em paralelo. É recomendado para arquivos maiores que 100 MB e obrigatório para arquivos maiores que 5 GB. Se a rede cair, ele retoma de onde parou.
  • 2. GET (Baixar/Ler): Recupera o objeto. Você pode baixar o arquivo inteiro de uma vez ou pedir apenas um intervalo de bytes (uma parte específica do arquivo), o que é ótimo para redes lentas.
  • 3. DELETE (Excluir) e a Mágica do Versionamento: A forma como a exclusão funciona muda completamente dependendo se o Versionamento (Versioning) está ativado ou não no seu bucket.
O que é o Versionamento? É um recurso de segurança que guarda o histórico de todas as modificações de um arquivo. Se você enviar um arquivo com o mesmo nome, em vez de sobrescrever e perder o antigo, o S3 empilha as versões (cada uma ganha um Version ID). Atenção: Uma vez ativado no bucket, o versionamento só pode ser suspenso, mas nunca totalmente desativado.
  • DELETE sem versionamento: O arquivo é apagado permanentemente. Fim da linha.
  • DELETE com versionamento: Se você mandar apagar um arquivo sem especificar qual versão, o S3 não apaga o arquivo. Ele apenas coloca um "Marcador de Exclusão" (Delete Marker) no topo da pilha. Se alguém tentar acessar, vai receber um erro 404 (Não Encontrado), mas o arquivo original continua seguro nas versões anteriores. Para apagar permanentemente, você precisa rodar o comando DELETE informando o Version ID exato.

5. Protecting data and managing access to Amazon S3 resources

Criptografia de Dados (Data Encryption)

A proteção dos seus dados ocorre em dois momentos distintos:

  • Em trânsito (In transit): Quando o dado viaja da sua rede para a AWS. É protegido nativamente por SSL/TLS (HTTPS).
  • Em repouso (At rest): Quando o dado já está salvo fisicamente nos discos da AWS. O S3 oferece três opções principais de criptografia no lado do servidor (Server-side Encryption - SSE):
    • SSE-S3: A própria Amazon cria e gerencia as chaves (usando o padrão AES-256). É a opção mais transparente e simples.
    • SSE-KMS: Usa o serviço gerenciador de chaves da AWS (Key Management Service). A grande vantagem aqui é a auditoria; você consegue ver exatamente quem usou a chave e quando.
    • SSE-C (Customer): Você, o cliente, cria e fornece sua própria chave. A AWS só usa a sua chave para embaralhar o arquivo na hora de salvar e desembaralhar na hora de ler, mas não guarda a chave.
Regra de ouro: Ativar a criptografia em um bucket não criptografa retroativamente os objetos que já estavam lá. A regra só se aplica aos novos arquivos enviados a partir daquele momento.

Gerenciamento de Acesso (Access Management)

Por padrão, absolutamente tudo no S3 (buckets e objetos) nasce privado. Para liberar acesso, você utiliza políticas:

  • Políticas Baseadas em Identidade (Identity-based): São criadas no serviço IAM e anexadas a usuários ou grupos (ex: "O usuário da Sofía tem permissão total no S3").
  • Políticas Baseadas em Recurso (Resource-based): São anexadas diretamente ao bucket ou ao arquivo. Dividem-se em duas:
    • ACLs (Listas de Controle de Acesso): Mais antigas e aplicadas nível a nível (no bucket ou em arquivos individuais). São muito usadas quando o dono do bucket é uma conta da AWS diferente da conta que fez o upload do arquivo.
    • Políticas de Bucket (Bucket Policies): Escritas em formato JSON e aplicadas ao bucket inteiro. Elas são muito granulares. Para a cafeteria hospedar o site, é aqui que você criará uma regra permitindo leitura pública anônima para a internet inteira.

URLs Pré-assinadas (Presigned URLs)

São links temporários (com validade máxima de 1 semana) que você gera para permitir que alguém sem conta na AWS faça download (GET) ou upload (PUT) de um arquivo específico. Quem clica no link "pega emprestada" a permissão de quem gerou a URL apenas para aquela ação.

CORS (Cross-Origin Resource Sharing)

É um mecanismo de segurança de navegadores web. Se o seu site roda em (https://www.site-da-cafeteria.com) e tenta carregar imagens direto de um bucket S3 em outro domínio (bucket.s3.amazonaws.com), o navegador bloqueia a ação. Você precisa configurar uma regra de CORS no seu S3 liberando explicitamente o seu site para puxar esses recursos.

Tarefa 3: Definição de uma política no bucket usando o SDK for Python

Agora que Sofía criou o bucket, ela quer definir as permissões no bucket. Ela quer que Frank, Martha e Nikhil consigam acessar a primeira versão do site que ela está criando para que possam ver o progresso até o momento. No entanto, ela ainda não quer expor o site ao mundo exterior. Ela concretizará esse objetivo configurando uma política de bucket no bucket. Esta política de bucket aplicará uma condição.

  1. Crie o documento de política.
    • No menu Explorer do painel de navegação do VS Code IDE: Selecione o Menu, clique em File (Arquivo) e, depois, New File (Novo arquivo).
    • Nomeie o arquivo vazio website_security_policy.json e selecione Create New File para criar o arquivo.
    • Clique em OK no prompt que mostra o caminho completo do arquivo.
    • No arquivo website_security_policy.json, cole o seguinte código:
    {
"Version": "2008-10-17",
"Statement": [
{
"Effect": "Allow",
"Principal": "*",
"Action": "s3:GetObject",
"Resource": [
"arn:aws:s3:::<bucket-name>/*",
"arn:aws:s3:::<bucket-name>"
],
"Condition": {
"IpAddress": {
"aws:SourceIp": [
"<ip-address>/32"
]
}
}
},
{
"Sid": "DenyOneObjectIfRequestNotSigned",
"Effect": "Deny",
"Principal": "*",
"Action": "s3:GetObject",
"Resource": "arn:aws:s3:::<bucket-name>/report.html",
"Condition": {
"StringNotEquals": {
"s3:authtype": "REST-QUERY-STRING"
}
}
}
]
}
    • No documento de política, substitua todas as três entradas <bucket-name> pelo nome real do bucket.
    • Por fim, substitua <ip-address> pelo endereço IP que está sendo usado para conectar seu computador à internet. É possível encontrar o endereço IP acessando whatismyip.com
    • Observação: não será possível visualizar o site se usar 0.0.0.0 como o aws:SourceIp permitido, pois a inteligência do Amazon S3 é suficiente para reconhecer que isso indica acesso público e bloqueará seu acesso. Portanto, use o endereço IPv4 específico. O arquivo é salvo automaticamente.
    Análise: este documento de política consiste em duas declarações. A primeira declaração permite solicitações GetObject do seu endereço IP. A segunda declaração nega acesso a um objeto no bucket chamado report.html, a menos que uma condição específica seja atendida.
  2. Aplique a política ao bucket usando o SDK for Python.
    • No painel de navegação, expanda o diretório python_3 e abra o arquivo permissions.py (que contém o código inicial).
    • Edite o arquivo substituindo <bucket-name> pelo nome do bucket. As alterações são salvas automaticamente.
    • Por fim, no terminal, navegue até o diretório python_3 e execute o seguinte código: 
      cd python_3
python3 permissions.py
    • Se o comando for concluído com êxito, você verá a mensagem DONE na saída do terminal.
    • Opcional: retorne à guia do navegador na qual o console do Amazon S3 está aberto e observe se a política foi aplicada ao bucket.
