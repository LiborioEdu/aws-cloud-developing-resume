2. Introducing to Developing on AWS

1. Systems development lifecycle

O principal desafio das empresas hoje é equilibrar a estabilidade de suas operações com a necessidade de lançar novas funcionalidades rapidamente. Para isso, o software precisa ser entregue de forma rápida (quickly), segura (securely) e confiável (reliably).

Para gerenciar esse desafio, utilizamos o SDLC (Systems Development Lifecycle), um modelo que divide o projeto em seis etapas: Planejar (Plan), Definir (Define), Projetar (Design), Desenvolver (Develop), Implantar (Deploy) e Manter (Maintain). O foco principal deste curso da AWS será nas fases de Desenvolvimento e Implantação.

Metodologias de SDLC: Cascata vs. Ágil

Existem diferentes formas de aplicar o ciclo de vida. As duas principais abordagens são:

Cascata (Waterfall): É o método tradicional e sequencial. Cada fase precisa ser totalmente concluída antes que a próxima comece. O grande problema aqui é a lentidão: a equipe pode passar meses sem receber nenhum feedback do cliente até que o produto final seja lançado.

Ágil (Agile): É a abordagem moderna e iterativa. O foco é lançar versões menores do produto o mais rápido possível para coletar feedback e melhorar nas próximas versões. O trabalho é dividido em ciclos curtos chamados Sprints, que duram de 1 a 4 semanas. Desenvolver na AWS facilita muito a adoção do modelo Ágil, pois a nuvem permite adaptação rápida a mudanças.

As 5 Grandes Fases do Desenvolvimento de Software

Dentro do ciclo de desenvolvimento, o código passa por cinco fases principais. Cada etapa serve para aumentar a confiança de que o sistema vai funcionar corretamente quando chegar ao usuário final:

  • Codificar (Code): Os desenvolvedores escrevem o código, salvam em um repositório (como o Git) e fazem revisões em equipe (peer-review) para garantir a qualidade.
  • Construir (Build): O código é compilado e testado automaticamente por máquinas. Aqui rodam os testes mais simples (testes de unidade) e verificações de estilo de código.
  • Testar (Test): O sistema é levado para um ambiente parecido com o real (pré-produção). Aqui acontecem testes mais pesados, como integração com outros sistemas, testes de carga (para ver se aguenta muitos acessos) e testes de segurança (penetration tests).
  • Implantar (Deploy): O código é finalmente liberado para o ambiente de produção (onde os clientes reais vão usar). O objetivo aqui é fazer isso com o menor risco possível.
  • Manter (Maintain): O sistema em produção passa a ser monitorado constantemente para detectar atividades incomuns, erros ou lentidão rapidamente.

2. Step to get started developing on AWS

A interação com os serviços da AWS é baseada em uma API (estilo REST) e pode ser executada de quatro formas integradas. Você pode, por exemplo, criar um servidor via código e depois excluí-lo pela interface gráfica.

  • Chamadas Diretas: Uso puro da API dos serviços.
  • AWS Management Console: A interface gráfica acessada pelo navegador.
  • AWS Command Line Interface (AWS CLI): Gerenciamento da nuvem por meio de comandos no terminal do seu sistema operacional.
  • AWS SDKs (Kits de Desenvolvimento): Bibliotecas embutidas no seu código para controlar recursos da AWS usando linguagens de programação populares.

Ferramentas de Linha de Comando e Desenvolvimento

  • AWS CLI: Ferramenta de código aberto e multiplataforma. A estrutura padrão de uso é sempre aws <serviço> <operação> [parâmetros].
    Exemplo: aws ec2 stop-instances --instance-id i-123.
  • AWS Tools for PowerShell: Módulos específicos para gerenciar a AWS usando o ecossistema e scripts do Windows PowerShell.
  • AWS SAM Local: Focado no desenvolvimento e teste local de aplicações serverless (sem servidor).
  • AWS Amplify: Framework voltado para criação e gerenciamento rápido de backends para aplicativos web e mobile (iOS, Android, React Native).

AWS CloudShell

É um ambiente de terminal executado diretamente no seu navegador, acessado por dentro do AWS Console, que simplifica a execução de comandos:

  • Zero configuração: Já utiliza as credenciais do seu usuário logado (pré-autenticado) e não exige instalação de chaves de acesso.
  • Pronto para uso: O ambiente (baseado em Amazon Linux 2) já vem com o AWS CLI, SDKs e outras ferramentas pré-instaladas.
  • Custo e Armazenamento: É gratuito e oferece 1 GB de armazenamento persistente por Região para você salvar seus scripts e arquivos de configuração.

Rodando a AWS localmente (Estudo)

Por questão de estudo, vou rodar a AWS localhost em um docker.

# Ativa o docker
docker run --rm -it -p 5000:5000 motoserver/moto

# Abrir outro terminal e agora você pode criar recursos e testar os serviços.
# A única regra de ouro da sua rotina é que todo comando precisa indicar o endereço do servidor local.
aws --endpoint-url=http://localhost:5000 s3 ls

# Ver se foi
aws --version

# Configurar credenciais

3. Desenvolvendo com AWS SDKs

Quando você usa um SDK, o fluxo é simples: sua aplicação faz um comando, o SDK transforma isso em uma requisição HTTP(S) e a envia para o Endpoint (a URL que serve como porta de entrada do serviço na AWS). O serviço processa e o SDK devolve a resposta traduzida para o seu código.

Para interagir com os serviços, os SDKs oferecem dois níveis de abstração:

  • API de Cliente (Service Client API): É a interface de baixo nível. Existe um método exato para cada operação da API da AWS (mapeamento 1 para 1). Oferece controle total sobre a requisição. Exemplo no Python (Boto3): boto3.client('s3').
  • API de Recurso (Resource API): É a interface de alto nível e orientada a objetos. Em vez de lidar com os detalhes brutos da requisição, você interage com abstrações mais lógicas (como um "Bucket" ou um "Objeto"). Nem todos os SDKs possuem essa API, mas ela deixa o código mais limpo. Exemplo: boto3.resource('s3').

Definindo Regiões (Specifying Regions)

A infraestrutura da AWS é global. Ao usar o SDK, você precisa informar em qual região seu código vai atuar. Isso geralmente é feito de duas formas:

  • No código: Passando a região como parâmetro na hora de criar o cliente (ex: region_name='us-east-1').
  • Via arquivo: Definindo uma região padrão no arquivo de configuração local do seu computador (~/.aws/config).

Tratamento de Erros (Handling Exceptions)

Toda chamada para a API retorna um código de status HTTP. Se for da série 200, deu tudo certo. Se der erro, você recebe um XML detalhado (com Código, Mensagem, Recurso e RequestID). Você deve reagir aos erros de duas maneiras:

  • Série 400 (Erro do Cliente): A culpa foi da sua requisição (ex: tentou acessar um recurso que não existe ou sem permissão). Você precisa tratar o erro no seu código.
  • Série 500 (Erro do Servidor): Falha interna da AWS. A solução é tentar novamente (retry).

Dica de Prova (Exponential Backoff): Os SDKs já fazem retries automáticos para erros 500 usando um algoritmo de espera exponencial. Isso significa que, se a primeira tentativa falhar, ele espera uma fração de segundo. Se falhar de novo, espera mais tempo, aumentando o intervalo progressivamente para não sobrecarregar a rede.

Tarefa 1: Exploração do AWS CloudShell

O AWS CloudShell é um shell pré-autenticado e baseado em navegador que você pode iniciar diretamente no Console de Gerenciamento da AWS. Nesta primeira tarefa, você estabelecerá conexão com o CloudShell e explorará seus recursos.

  • No Console de Gerenciamento da AWS, na parte superior da tela, selecione o ícone AWS CloudShell.
  • No prompt do CloudShell, verifique se a AWS CLI está instalada:
aws --version
  • Teste a capacidade de executar um comando simples da AWS CLI:
aws s3 ls
  • No menu Actions (Ações), selecione Tabs layout > Split into columns. Uma segunda janela do terminal é aberta demonstrando que você pode ter vários painéis.
  • Baixe o arquivo list-buckets.py. No menu Actions (Ações), selecione Files > Upload file e faça o upload do arquivo para o terminal.
  • No terminal do lado direito, visualize o arquivo carregado:
cat list-buckets.py

# A saída mostra o conteúdo:
import boto3
session = boto3.Session()
s3_client = session.client('s3')
b = s3_client.list_buckets()
for item in b['Buckets']:
    print(item['Name'])
  • Execute o código do SDK for Python:
python3 list-buckets.py
  • Para copiar o arquivo list-buckets.py para o seu bucket S3, execute o seguinte comando:
aws s3 cp list-buckets.py s3://<bucket-name>

Nota: Ao usar o AWS CloudShell, você tem armazenamento persistente de 1 GB para cada região AWS sem custo adicional. Os dados no diretório inicial ($HOME) persistem entre as sessões.

Tarefa 2: Exploração do VS Code IDE

Nesta tarefa, você se conectará ao VS Code IDE e aprenderá a usá-lo. Você também interagirá com o Amazon S3 por meio do VS Code IDE.

  • Na parte superior destas instruções, selecione Details > AWS: Show. Copie os valores LabIDEURL e LabIDEPassword.
  • Em uma nova guia do navegador, cole o valor de LabIDEURL para abrir o VS Code IDE.
  • Insira a senha e observe a interface (terminal Bash na parte inferior, painel de navegação na lateral). Esse ambiente é executado em uma instância do Amazon EC2.
  • No terminal Bash, obtenha o nome do seu bucket executando: aws s3 ls
  • Baixe o arquivo list-buckets.py do S3 para o IDE (não esqueça o ponto no final):
aws s3 cp s3://<bucket-name>/list-buckets.py .
  • O Python 3 já está instalado, mas as bibliotecas do SDK (Boto3) não. Se você tentar rodar o código, dará o erro ModuleNotFoundError. Instale o Boto3:

python3 list-buckets.py
  • Crie um novo arquivo html (File > New Text File), adicione o texto <body> Hello World. </body>, e salve como index.html.
  • Faça o upload do arquivo para o bucket do S3:
aws s3 cp index.html s3://<bucket-name>/index.html
